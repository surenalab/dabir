# Dabir plan

The full plan with the design brief and architecture is rendered at [docs/plan.html](docs/plan.html) and published at https://claude.ai/code/artifact/5c6592e1-1c27-46a5-8ff2-728e977bed72. This file is the working summary: what is done, what is next, and the decisions that were made along the way.

## State and next steps (2026-09-12)

**Built and verified on macOS:** editing (visual, source, split, formatting bar, completion, prediction, spelling, grammar on demand), compile with traceable problems and agent fixes, SyncTeX both ways, PDF tools, Git, agent runs on worktrees with in-document review, model and effort control and hunk-level accept for five vendors, repository memory and skills, live sessions over three transports with full-tree mirrors, comments with threads and PDF pins, templates, Typst with its own visual layer, Zotero, offline LaTeX-aware spelling, updater, release workflow. v0.1.1 draft release has Windows and Linux installers; macOS DMGs wait on notarisation.

**2026-09-10, agent surface and saving.** The agent panel shows a transcript: thinking folded into "Thought for n s" (live while running), the agent's prose in full, tool calls as compact rows with a verb (Read, Edited, Ran, Compiled, Searched), the target and the time since start, grouped in bursts; a result card with duration, files, +/− and whether it compiled; Accept now lands the changes in the checkout and takes a snapshot without a commit, with Accept and Commit and Open Pull Request under a disclosure. Autosave writes the file about a second after typing stops (toolbar shows Saving…/Saved), compile-on-save becomes compile-after-changes-settle, and snapshots go to `refs/dabir/checkpoints` every five minutes and after each accepted agent change; Versions in the sidebar restores any of them, and restoring snapshots the state it replaces. The user's branch and index are never touched by snapshots.

**2026-09-10, harden and bench.** Accept without commit now logs to `.dabir/memory/runs.md` and forces a buffer reload (cancelling a pending autosave so a dirty editor cannot overwrite the applied patch). Live thinking shows “Thought for n s…”; streamed prose and thought coalesce; review copy matches Accept-without-commit. Versions lists all snapshots via Show more. Bundle split: PdfView lazy-loads, pdf.js / KaTeX / Yjs / CodeMirror are separate chunks (main JS ≈ 353 KB gzip 111 KB, down from a single 1.8 MB chunk). Visual decorations skip a full rebuild when the caret stays on the same line. `bench/` holds twenty repair and revision tasks on score-anchor plus `./bench/run.sh <provider> [task]`; smoke with Grok passed `01-strong-baselines` in 12.8 s.

**2026-09-10, bench results and track changes.** Full suite on the four signed-in CLIs (table in `bench/README.md`): Grok 20/20, Claude Code 19/20, Cursor 18/20, Codex 0/20 because the account was at its usage limit (19/20 once it reset, mean 40 s; the one miss hung past the cap and passed on rerun). The failures taught two things and fixed two bugs: the Codex CLI's error text (`{"type":"error","message"}`) was swallowed as a bare failure and now reaches the transcript; and when an agent regenerated the sample's figure PDF, Accept failed because the patch went through a lossy UTF-8 conversion before `git apply`, so patches are now byte-exact end to end (`filter_patch_bytes`). Task 13 accepted `$A$` as well as `A`. Single-task runs write `<provider>-<task>.json` instead of clobbering the suite's file. Track changes shipped: Suggest changes (pen in the formatting bar, People tab, Settings) turns typing into underlined insertions and deletions into struck text that stays in the file, per author colour, both in the source and in Visual prose. The marks live in a CodeMirror state field that follows the text; a transaction filter rewrites the user's edits while suggesting is on (a deletion inside your own pending insertion really deletes; adjacent strikes merge; a replace strikes the old and inserts the new after it); programmatic dispatches, remote Yjs updates and undo pass through untouched, and undo restores the marks along with the text. Accept and Reject per change from the hover card or the People list, or all at once; accepting a deletion removes the text, rejecting an insertion removes it. Storage mirrors comments: `.dabir/changes.json` with offset-plus-quote anchors when alone (written once typing settles), the shared `changes` array with Yjs relative positions in a session. Verified with a headless CodeMirror test of the filter (insert, grow, own-delete, strike, merge, replace, resolve, undo/redo) and a CDP-driven run of the preview. Review pass (Bugbot, security): session sync now merges by id so a coauthor's record this client has not yet seen survives a stale write, and colours from peers or files must be hex before they reach a style attribute. Visual view: a widget whose source holds a suggestion wears it, since the replaced text cannot show the mark itself: inline math and chips take the underline or strike in the author's colour; equations, figures, tables and the preamble fold get a faint wash, a hairline and a one-line label with the author's dot ("Ada suggests an insertion"); clicking reveals the source with the marks, and the badge disappears when the suggestion is resolved. The visual field rebuilds when the suggestion set changes.

**2026-09-10, review in the document, steering, spelling, Typst.** Agent runs now start from the working copy: the worktree is seeded with the uncommitted edits and untracked files (one "Working copy at run start" commit on the run branch), so nothing has to be committed before asking. After a run the open file switches to the agent's version, read-only, with insertions and word-level edits marked in the editor; ⌘B compiles the agent's tree (the status bar says whose version compiled) and the banner toggles between the two texts, accepts into the working copy or rejects. Accept applies to the working tree only (plain `git apply`, three-way as a fallback) and no longer needs the index to match, which was the "commit before you can compile" complaint. The agent transcript is a fixed-height window that follows the run and stops following when you scroll up; the agent's prose renders as paragraphs, lists, headings and code rather than raw model output; bursts of reads and searches fold into one row ("Read 4 files"); paths are relative to the paper. Each provider gets a Model and an Effort control in the composer, filled from the installed CLI (`claude --model/--effort`, `codex -m -c model_reasoning_effort`, `cursor-agent --model` with effort in the model id, `grok --model --reasoning-effort`), with Other… for a model the list does not know; the choice persists per provider and the run's header shows it. Colours from files and peers are checked before reaching any style attribute (comments, replies and local `comments.json` included). Remote cursors show in Visual view: a widget whose hidden source holds a coauthor's caret wears a name tag in their colour, and the tag leaves with the caret. Spelling is offline and LaTeX-aware: a Hunspell engine (nspell) with bundled British and American dictionaries checks only prose (commands, math, verbatim, URLs and reference arguments are skipped), underlines misspellings, and a hover card offers ranked suggestions (letter swaps first), Add to Dictionary (`.dabir/dictionary.txt`, committed with the paper) and Ignore; Settings choose UK, US or the system checker. Typst files get a visual layer built on the same widgets: headings, figures with captions, citation and reference chips, links, footnotes, includes, list bullets, strong and emphasis, hidden labels, and the leading set/show/import rules folded into a preamble row. Second pass the same day: Typst math is translated to LaTeX (`src/lib/typst-math.ts`: a small recursive-descent parser over Typst's math tokens handling scripts with parenthesised groups, `/` fractions, calls such as `frac`, `sqrt`, `root`, `mat`, `vec`, `cases`, accents, `bold`/`cal`/`bb` styles, `abs`/`norm`/`floor`, quoted text, alignment rows and about two hundred symbol names) and rendered through KaTeX; when the parser or KaTeX cannot follow, the source keeps its math styling, so nothing renders wrongly. Display math on its own line is a block with a live preview while editing and a number when labelled. `#table(...)` and `#figure(table(...))` become tables with header rows and captions; a show rule's `title:` and `authors:`, or the template's centred title line, become the title block; `*Abstract.*` takes the abstract style. Bench rerun on the new run path, four providers in parallel: Grok, Codex, Claude Code and Cursor each 20/20 on the first attempt (means 24, 33, 35 and 44 s; table in `bench/README.md`). A persisted retrieval index was considered and dropped: `memory::context_pack` already runs BM25 over every `.tex`, `.bib`, code and memory file at run start, which for paper-sized repositories takes milliseconds, so an on-disk index would add a cache to keep coherent without a measurable gain.

**2026-09-10, history.** The owner's test of the built app: an uncommitted edit made just before asking the agent for more was gone after Accept, and "Versions" hidden under the Changes panel was not a way to track or reverse what happened. Two loss paths closed: a dirty buffer is written to disk before a run starts and before Accept lands (runs used to start from the last autosave and Accept reloaded the file from disk over unsaved keystrokes); the editor is read-only while the agent's version is showing. History replaces Versions: a tab in the inspector, newest first, grouped by day, one step per save session (saves of the same file within three minutes fold into one snapshot) and one per accepted agent change ("Grok: add a figure"), each with its files and +/−; open a step to read its diff; Undo this step takes only that step out with `git apply -R` and refuses when later edits overlap it; Restore to here puts the paper back to that point. Both snapshot the current state first, and restore records the restored state as a step, so the chain always reads forward. Snapshots grow from the branch commit and carry a `Dabir-Snapshot` trailer so the walk knows where the chain ends. The Changes panel gains Discard per file (snapshotted first) and a History link. Nothing in History is a commit; Commit stays explicit. Also: the review banner's Agent's version toggle no longer wraps.

## How the pieces work

- **Visual editing.** One CodeMirror buffer, two views. A state field rebuilds decorations on every document or selection change: line classes for headings, abstract and preamble; replace-decorations that hide `\section{`, `\emph{`, labels and scaffolding lines; KaTeX widgets for `$…$` and equation environments; figure widgets that render the first page of the figure PDF; chips for `\cite`, `\ref` and `\input`. Any construct that intersects the selection is left as source, so clicking a widget places the cursor inside and reveals it.
- **SyncTeX.** Rust parses `main.synctex.gz` into (page, x, y, file, line) records. Clicking a PDF page finds the nearest record and jumps the editor. Show Line in PDF finds the record for the cursor line and draws a marker on the page.
- **Agent runs.** `agent_run` creates `.dabir/worktrees/<id>` on branch `dabir/<id>`, prepends a pointer to the project brief, and spawns the vendor CLI there with permission prompts bypassed. stdout lines are parsed per vendor (Claude and Cursor stream-json, Codex exec json, a generic fallback for Grok and OpenCode) into text, tool, log and done events. The worktree starts from the working copy, not HEAD. On done the front end asks for the worktree diff and shows the agent's version of the open file in the editor with the changes marked; ⌘B compiles the worktree. Accept applies the patch to the working tree with a plain `git apply` (three-way as a fallback), never touching the index, and removes the worktree; Accept and Commit also commits. Reject removes it. Open Pull Request commits on the branch, pushes, and runs `gh pr create --web`.
- **Memory.** `memory_setup` writes a deterministic brief (title, class, sections, figure files, provenance commands), an empty provenance file, `AGENTS.md`, `CLAUDE.md` and a Cursor rule, all pointing at the brief. `memory_read` merges provenance from `provenance.json` and `dabir.toml`, and marks an artefact stale when any input is newer than it. Rerun executes the recorded command and stamps the date and commit.

**2026-09-07, live agent runs.** The full worktree pipeline was run against real CLIs with the ignored test `live_agent_run`: Grok finished the edit in 11 s and Codex in 30 s, both diffs applied and committed cleanly. Discoveries folded back into the adapter: Claude Code ships inside the VS Code agent-host cache and Codex inside ChatGPT.app when no standalone CLI is on PATH; Codex's current exec flags are `--json --skip-git-repo-check --dangerously-bypass-approvals-and-sandbox`; Grok's `streaming-messages-json` is the Claude stream format; a child CLI must not inherit the parent session's `ANTHROPIC_BASE_URL` and `CLAUDE_CODE_*` variables; `.dabir/worktrees` has to be excluded through `.git/info/exclude` or the accept commit tries to add it. ## Agent context design

Minimal on purpose. Three files an agent reads, in this order, all committed with the paper:

1. **`.dabir/PROJECT.md`, the identity.** Under 80 lines: Identity (abstract-sized), Claims and key numbers, Conventions (macros not to redefine), Repo map (one line per code file with its docstring), How to run (detected from environment.yml, pyproject, requirements, Makefile; the `[env] prefix` every command gets), Generated artefacts (artefact → command), Working rules. Drafted deterministically from the manuscript by Set Up Memory; humans and agents both edit it.
2. **`.dabir/skills/<job>/SKILL.md`, the know-how.** Six playbooks for the recurring jobs: rerun-experiment, update-figure-and-text, address-reviewer, tighten-prose, check-references, compile-and-fix. Standard Agent Skills format with `name` and `description` frontmatter, so Claude Code, Codex and Cursor discover them through `.claude/skills` and `.agents/skills` symlinks without any vendor-specific glue.
3. **`.dabir/memory/`, what was learned.** One fact per file with frontmatter, plus `runs.md`, appended on every accepted run (date, provider, request, files).

At run time Dabir prepends a preamble of about ten lines: the identity sentence, the pointer, the env prefix, the skill names, and the context pack (top passages by BM25 over `.tex`, `.bib`, code, the brief and the facts, capped at about 2 KB). In the live tests every provider's first action became reading the brief or jumping straight to the right line.

## Decisions

- **Name:** Dabir (دبیر), Persian for scribe. Alternatives were Resaleh and Daftar.
- **Licence:** AGPL-3.0 for the app, MIT for packages that graduate. Reviewed 2026-09-13 against "a large company uses it without credit": the AGPL is already the strongest widely accepted copyleft (a company that modifies Dabir or runs it as a service must publish its source under the AGPL; most large companies forbid AGPL code internally for that reason), but no open licence can force *prominent* credit. What credit the AGPL does require is kept by the notices in the source and the About panel's legal notice, which a modified version must preserve. The name and the mark are protected separately (TRADEMARK.md): a fork or a service cannot be called Dabir. The CLA keeps the option of a commercial licence for the hosted relay or for companies that cannot accept the AGPL. Source-available licences (BSL, SSPL, Elastic) were rejected: they would forfeit the open-source standing that the research audience and the agent vendors' ecosystems expect.
- **Tauri over Electron** for native chrome, small binaries, and Rust for Git and process control. Electron stays the fallback if WebView rendering bites.
- **Tectonic** as the compile engine, looked up in Homebrew paths, PATH, or `DABIR_TECTONIC`. Bundling as a sidecar comes with packaging.
- **No model proxying.** Each vendor's own CLI runs locally with the user's subscription. Dabir is the control plane.
- **Design process.** Impeccable for direction and craft, the Apple HIG skill for platform correctness. Every UI change runs `/impeccable critique` before merge. Sample data is always tagged as sample in the UI.
- **Sample script is dependency-free** so the example runs anywhere, even though real projects will use matplotlib or whatever the paper's code uses.
